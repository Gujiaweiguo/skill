# Static Analysis & Reverse Engineering — 安装包静态分析与问题驱动的定点逆向

本文件定义对**已获授权且合法持有**的竞品安装包/交付包做静态盘点、问题驱动的定点逆向（窄深读），以及与授权 demo 取证的分工规则。

**权威位置分工**（本文件不复制定义，只定义流程与操作纪律）：

- 字段与枚举唯一权威：`evidence-ledger.md`（evidence_kind / source_type / source_version / source_sha256 / artifact_locator / verification_status / usage_scope / limitations）
- 合规红线唯一权威：`safety-and-ethics.md`
- 能力层校验规则：`capability-schema.md`

## 授权前提（先于一切操作）

1. **安装包来源合法**：竞品方提供 / 客户在合同与交付范围内提供 / 公开渠道获得。来源不明 → 拒绝执行，按 `safety-and-ethics.md` 冲突流程处理。
2. **合法持有 ≠ 拥有所有分析与传播权利**：EULA、保密协议、客户合同中的使用限制条款必须先核对。发现冲突时**单列记录**（conflict 条目，进 review/pending-items），按既有冲突流程处理；不得把"合法持有"自动解释为可任意分析、可对外传播。
3. **不要求每次重复确认已明确的授权**：已确认过的授权范围（同一来源、同一限制条款）复用时不再走确认流程；但新包、新版本、新限制条款出现时必须重新核对。
4. **静态分析是只读操作**：不安装、不修改、不运行安装包内容（运行包内服务/脚本见「禁止事项」）。

## 方法论：宽盘点、窄深读

### 第一层：宽盘点（inventory，有授权安装包时默认执行）

对安装包做全量结构盘点，产出**候选清单**而非能力结论：

- 包 / 模块 / 接口 / 资源 / 配置清单（如 `unzip -l` / `jar tf` / .NET 程序集清单 / 前端 chunk 清单与静态路由表）
- 数据库结构（包内 DDL、迁移脚本、初始化 SQL）
- **第三方依赖与业务代码先区分**：先识别第三方库与运维组件（Maven/Gradle 依赖清单、package.json、LICENSE 文件、第三方 UI 组件库特征），再盘点业务代码。**禁止按 JS/JAR 文件总数推断产品规模**。
- 产出：包结构盘点表（模块 / 载体 / 第三方标记 / 锚点）→ raw 层 `package-analysis/`。

宽盘点只支持 `evidence_kind=structure` 的结构观察主张（"该版本包内存在 X 结构"），不得据此宣称功能已部署或可用。

### 第二层：问题登记（窄深读的准入条件）

每次定点深读必须先登记一个**明确的业务问题**（question），如："免租期是否支持分段？""合同状态机是否含『已结案』状态？"。问题来源：

- S1 分析的待验证项（review/pending-items）
- demo 观察与手册/结构的冲突点
- 宽盘点中发现的候选结构

**无明确问题的"顺手全量反编译"不允许**——超出最小必要范围，拒绝执行。

### 第三层：窄深读（targeted read，最小必要范围）

- 范围 = 登记问题指向的目标模块 / 类 / 方法。不做超出问题的全包反编译。
- 只读分析：反编译 / 字节码查看 / 常量与字符串检索。产物是**投影**（projection），不是原始代码。
- **Java/C# 优先是工具与成本选择**（反编译工具链成熟、字节码可读性高），**不是对其他语言的永久禁令**；其他语言按同一纪律（问题驱动 + 最小必要 + 只读）个案评估。
- **每次深读必须记录**（进 evidence-ledger 或取证记录）：

| 项 | 说明 |
|---|---|
| 具体业务问题 | 登记的 question 原文 |
| 目标模块 | 类 / 方法 / 资源定位 |
| 工具及版本 | 如 CFR 0.152 / javap 17.0.x / ILSpy 8.x |
| 原件哈希 | 安装包归档的 SHA-256（`source_sha256`）|
| 分析锚点 | `artifact_locator`（类/方法/描述符 + 归档哈希；反编译行号仅作投影辅助）|
| 结果 | 回答了什么、部分回答了什么 |
| 未解决项 | 工具失败 / 混淆 / 超出范围 |

### 反编译失败的处理

反编译失败、代码混淆无法读、工具崩溃 → 该项标 `evidence_state=not_scanned` 或 `inaccessible` + `limitations` 注明原因，**不得标为功能缺失**（not_found / implementation_status=missing）。

## 三层归档（统一存储，元数据约束消费）

| 层 | 内容 | 约束 |
|---|---|---|
| `incoming/competitor-<vendor>/packages/` | 安装包 / 交付包原件 | 不因转换完成自动删除；记录来源与获取日期 |
| `raw/prd-商管系统/02-competitors/<vendor>/04-产品功能/package-analysis/` | 结构提取、反编译投影、工具输出、取证记录 | 反编译代码全文只留此层（gitignored）|
| `materials/13-competitors/<vendor>/04-产品功能/` | 可检索、可复核的**摘要**（`包结构盘点摘要.md`、`定点代码分析.md`）| 不把大量反编译代码全文复制进 materials；每条摘要保留来源、锚点、范围、限制 |

- **implementation 摘要可以入 materials**（默认 `usage_scope=internal-product-research`），完整反编译代码只留 raw。
- **不采用"不落库、不留来源"的隐性研究方式**：任何分析结论必须有台账条目和原件锚点；禁止只在会话或临时文件里研究不留痕。
- 单一消费者（仅 OPC 使用资料库）不是实际访问控制，也不消除许可或保密义务。

## demo 与静态分析分工

| 阶段 | 产出 |
|---|---|
| 静态分析（宽盘点 + 窄深读）| 候选模块、实体、规则、**待验证问题清单** |
| 授权 demo | 核对实际菜单、关键页面字段、联动、流程与报表结构 |

- **包内菜单与 demo 可见菜单分别记录并对照**（menu-parity 对照表）：不假定包内路由全集 = 功能全集，也不假定 demo 菜单 = 完整能力。
- **优先复用既有取证**：已抓取的页面 / 已有快照不重复采集，只补真正的缺口。
- **demo 默认只读**：不默认执行会写入业务数据的新增、提交、审批、删除等操作。确需写操作验证流程时须单独确认（测试环境 + 可清理 + 授权范围允许）并留痕。
- **交叉核对而非自动互证**：代码观察与运行行为可交叉核对；无法复现时保留静态限定（`verification_status=static-only`），不自动判功能不存在。
- **demo 窗口紧**：优先保全授权范围内的只读观察，但**不得把未完成的交叉核对标为 cross-checked**（规则见 `evidence-ledger.md`）。
- **版本一致性**：安装包版本与 demo 环境版本未确认一致时，两条来源**分别记录**（各自 `source_version` / `applies_to`），不得拼接成同一部署状态，也不得互证升级 confidence。

## 与 S0/S1 阶段的关系

- 本文件全部操作属于 **S0 采集取证阶段**（产物入三层），不做能力矩阵、不做改进建议、不做 PRD。
- 窄深读的问题可以来自 S1 的待验证项（review 回流），但深读产物仍归 S0 三层。
- S1 消费这些证据时按 `evidence-ledger.md` 的认识论上限执行：structure 只支持结构层主张，implementation 只支持实现层主张；"功能已部署/已启用/可运行"主张需 runtime 或 document 在匹配版本内佐证。

## 禁止事项（详见 safety-and-ethics.md）

- 未授权获取源代码、安装包或账号
- 许可证破解、修改授权判断、绕过访问控制
- 漏洞扫描、攻击性测试、压力测试
- 运行安装包中的服务或脚本作为默认采集步骤（任何运行需求按冲突流程单独评估：隔离环境 + 授权范围 + 留痕）
- 将第三方实现代码（依赖库或竞品业务代码）直接复制进蓝联业务代码——分析结论可借鉴，代码不可复制
