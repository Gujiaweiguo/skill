# 四看战略分析框架（通用引擎）

本文件是 strategy-brief-generator 内置方法论的权威定义。多公司架构（`/opt/code/docs/COMPANIES.md`）下作为**通用引擎**；各公司通过 company.yaml `strategy.methodology_ref` 实例化（如 lanlnk → 明源战略模板资料位；null 则直接用本文件）。

## 框架来源

- **通用引擎**：本文件（内置四看）。
- **实例化（可选）**：`methodology_ref` 指向的多份资料经 P2 归纳后作为补充子维度**入库** `materials/10-methodology/方法论归纳-<来源>-<日期>.md`（带 frontmatter；归纳过程稿留 raw/<主题>/）。同一份资料兼任方法论模板与竞品证据时必须区分双重角色——归纳框架时它是模板，P3 抽取时它是证据之一，且模板是参考框架不是真理。

## 四看 → 定战略 → 执行计划

### 一、看市场（Market）

回答：**市场正在发生什么变化？客户面临什么压力？**

| 分析维度 | 关注问题 | 资料来源 |
|---------|---------|---------|
| 行业趋势与宏观环境 | 增量/存量、消费变化、数字化渗透率 | `incoming/<主题>/`（市场趋势资料）+ web search |
| 客户变化与需求演变 | 客户经营模式转变、刚需化方向 | `incoming/<主题>/` + SOP |
| 技术变化 | AI/RAG/BI/低代码/私有化大模型趋势 | `incoming/<主题>/`（AI 趋势资料）+ web search |
| **政策与监管环境** | 政府行业政策、监管趋势、合规压力、**政策机会窗口** | `incoming/<主题>/`（政策文件）+ web search（政府官网文件优先） |

**政策升格规则**（company.yaml `industry_profile.policy_driven`）：
- `true` → P5 必产出 `materials/03-products/政策与市场/政策监管信号.md`（带 frontmatter 直产入库）（本地政策文件逐份摘录 + 联网检索，带发文字号/URL），简报看市场章节政策为独立小节
- `false` → 政策并入常规市场信号（维度保留、权重降低）

**输出要求**：每条市场信号标注来源；区分"行业共识"和"少数观点"。

### 二、看竞对（Competitors）

回答：**竞品在做什么？他们的打法和弱点是什么？**

按 `incoming/<主题>/` 中竞品原始资料的实际分类分组分析（分类由公司域知识决定；监管侧工具/标杆项目可与商业竞品并列分组）。

| 分析维度 | 关注问题 |
|---------|---------|
| 竞品定位与产品矩阵 | 全套系统？垂直工具？SaaS 还是私有化？ |
| 核心能力与特色打法 | 哪个模块/场景最强？ |
| 客户打法与生态策略 | 主攻头部？中部？代理渠道？监管背书？ |
| AI/数据能力 | 有没有 AI 问答/BI/智能分析/智能体？ |
| 价格/交付/服务模式 | 标准产品？定制？实施周期？ |

**输出要求**：竞品能力矩阵 + 每家竞品的战略主张 JSON；厂商自述能力标注"未实测"。

### 三、看自己（Self）

回答：**当前公司现在有什么？能做什么？缺什么？**

按 company.yaml `products` 逐产品盘点：

| 资产来源 | 盘点维度 |
|------|---------|
| code_root 非空（源码） | 已有模块、能力成熟度、技术栈、与竞品差距 |
| code_root 空（materials 资料） | 产品功能、已交付案例、行业覆盖、与竞品差距 |
| prd_ready: true | 直接复用 PRD/功能清单作权威能力基线 |
| 案例与交付 | 标杆案例、实施方法论、服务团队、客户口碑 |
| 组织与资源 | 团队规模、技术能力、资金、合作伙伴 |

**关键原则**：诚实面对短板。不夸大已有能力，不回避明显缺口。证据不足时同步产出资料缺口清单。

### 四、看机会（Opportunity）

回答：**市场缺口在哪？自身优势交叉点在哪？AI 新机会在哪？**

| 机会类型 | 推导逻辑 |
|---------|---------|
| 市场缺口 | 客户需要但没人做好的 |
| 竞品弱点 | 竞品做不好或没做的（含厂商自述的短板） |
| 自身优势交叉点 | 现有产品组合 × 市场/政策需求的交集 |
| AI/RAG 新机会 | 从 SOP 推导出的 AI问数场景 + RAG 知识场景 |
| 政策机会窗口 | 政策强制/试点带来的时限性需求（政策驱动型行业重点） |

**输出要求**：每个机会点标注市场规模感知（大/中/小）、竞争激烈度、自身匹配度；**结构化平铺为 `$STRATEGY_ROOT/产品机会清单.md`**（证据 ID 回链 evidence-ledger，确认后经 onboard.sh product 反哺公司产品台账）。

### 五、定战略（Strategy）

基于四看，输出战略定位。

| 战略要素 | 内容 |
|---|------|
| 战略定位声明 | 一句话讲清当前公司在目标行业的位置（主语用 $BRAND） |
| 目标客户画像 | 主攻哪类客户 |
| 差异化主张 | 相对主要竞品的独特价值 |
| 产品组合策略 | 现有产品 + 机会产品怎么组合 |

**关键原则**：战略定位要能被一句话讲清。讲不清说明没想清楚。

### 六、执行计划（Execution）

| 动作类型 | 内容 |
|---|------|
| 阶段目标 | P0（最小闭环/证据补齐）/ P1（增强）/ P2（深度） |
| 产品路线图 | 先做什么、后做什么 |
| 市场与售前动作 | 标杆案例打造、行业活动、售前物料 |
| 交付能力建设 | 实施团队、合作伙伴、SaaS 化 |

## 框架使用注意

1. **四看不是线性流程**：分析过程中可能反复回到前面的"看"补充证据。
2. **看自己要诚实**：高估自己能力是战略分析最常见的错误。
3. **看机会要具体**：不要写"AI 是大机会"这种空话，要写清楚场景、证据与政策依据。
4. **定战略要收敛**：四看分析可能发现 10 个机会，战略只能选 2-3 个重点。
5. **执行计划要可验证**：每个阶段目标要有验收标准。
6. **政策驱动型行业先看政策**：政策信号往往是市场判断与机会窗口的第一证据源。
