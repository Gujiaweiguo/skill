# strategy-brief-generator Troubleshooting

本文件记录战略分析过程中的非显而易见问题和诊断流程（通用引擎部分）。
公司专属诊断条目在各公司 `config/sales-playbook/strategy-brief.md`（P0 加载；如 lanlnk 的 B/D 路线、岗位行集对齐等）。

## 已知问题

### 方法论实例化资料归纳冲突

**症状**：`methodology_ref` 指向的多份方法论资料章节结构不一致，归纳时不知道以哪个为准。

**原因**：不同时期的方法论资料可能用不同框架（如有的用"五看"、有的用"四看"、有的是自由结构）。

**处理**：

1. 以"四看 → 定战略 → 执行计划"为主线。
2. 其他模板里有价值的维度，作为四看的补充子维度。
3. 差异记录写进 raw/<主题>/ 归纳过程稿；统一框架入库 `materials/10-methodology/`。
4. 不要强行合并互相矛盾的方法论；标注冲突，让用户决策。
5. `methodology_ref` 为 null 的公司直接用内置四看（`references/four-look-framework.md`），无此问题。

### 竞品资料不完整导致能力矩阵出现空格

**症状**：某家竞品资料很少，能力矩阵大量空白。

**原因**：小众竞品公开资料少，可能只有一份 PPT 或官网截图。

**处理**：

1. 空白格标注"资料不足"，不要填"未发现"（未发现 ≠ 不存在）。
2. 用 web search 补充公开信息。
3. 仍然不足的，在 `待确认事项.md` 里登记"需补充 XX 竞品资料"。
4. 不要因为资料少就低估竞品——小众竞品可能在某个垂直领域很强。
5. 厂商自述的能力一律标注"未实测"。

### 源码能力盘点过浅

**症状**：源码类产品盘点只到模块名，没有能力细节。

**原因**：源码量大，第一版只做模块级盘点是合理的。

**处理**：

1. 第一版接受模块级盘点，在《自身能力盘点》中标注盘点深度。
2. `prd_ready: true` 的产品优先复用其 PRD/功能清单补充能力细节（避免重新读码）。
3. 源码盘点 README、路由、主要 service 类即可。
4. 不要为了"盘点完整"而陷入源码细节——战略分析不需要字段级精度。

### 市场搜索结果质量参差

**症状**：web search 返回的市场趋势资料质量不一，有的权威、有的是营销软文。

**原因**：多数行业的公开研究报告质量差异大。

**处理**：

1. 优先采信：行业头部机构报告、**政府/监管官方文件**、上市公司财报。
2. 谨慎采信：厂商白皮书、媒体软文、知乎/公众号观点。
3. 不采信：无来源的"行业共识"、AI 生成的趋势文章。
4. 每条市场信号标注来源类型（权威/一般/待验证）。
5. 政策驱动型行业（`policy_driven: true`）：政策信号必须回溯到发文字号或官网 URL，二手解读只能作线索。

### SOP 资料覆盖不全

**症状**：行业 SOP 只覆盖部分业务领域。

**原因**：SOP 资料通常来自单一客户或单一项目，覆盖面有限。

**处理**：

1. 有什么 SOP 分析什么，不要伪造缺失部分。
2. 缺失部分标注"待补充 XX 领域 SOP"。
3. 可以用竞品资料中的业务流程描述作为 SOP 的补充证据（标注来源为竞品而非客户 SOP）。

### 战略判断变成竞品功能对比

**症状**：战略简报变成"竞品 A 有功能 X，我们也应该做功能 X"。

**原因**：这是战略分析最常见的陷阱——把竞品对标当成战略。

**处理**：

1. 竞品功能对比是"看竞对"的输入，不是"定战略"的结论。
2. 定战略要回答"当前公司应该做什么"，不是"竞品做了什么"。
3. 每个"应该做"的建议，必须连接到四看中的至少两个维度（如：市场需要 + 自己能做）。
4. 单纯"竞品有所以也要有"的建议，标注为低置信度假设。

### AI 场景推荐过度泛化

**症状**：战略简报里到处是"用 AI 提升效率"、"用 RAG 实现智能问答"。

**原因**：没有基于 SOP 推导具体场景，泛泛而谈。

**处理**：

1. 每个 AI 场景推荐必须连接到具体 SOP 流程或具体业务痛点。
2. 用 `SOP到AI问数场景映射.md` 和 `SOP到RAG知识场景映射.md` 作为依据。
3. 没有场景支撑的 AI 建议，标注为"待验证假设"。
4. 区分 AI问数 / RAG / AI助手 / AI决策，不要混为一谈。

## 诊断流程

### 战略简报质量自检

生成战略简报后，按以下清单自检：

```text
□ 管理层摘要能否一句话讲清战略定位？
□ 四看的每个维度是否都有证据支撑？
□ 看自己是否诚实面对了短板？
□ 定战略是否收敛到 2-3 个重点？
□ 执行计划是否有可验证的阶段目标？
□ AI 场景推荐是否都连接到了具体 SOP？
□ 证据台账是否完整（每条判断可追溯）？
□ 是否有未标注的假设（混在判断里）？
□ 是否有越界内容（PRD 字段、客户方案叙事、报价）？
□ 产品机会清单的每条机会是否都有证据 ID 回链？
□ 政策驱动型行业是否产出了独立的政策监管信号文件？
```

### 资料覆盖度评估

分析开始前，评估资料覆盖度：

```text
资料覆盖度 = {
  methodology: methodology_ref 有几份资料？结构是否完整？（null 则跳过）
  market: 本地市场资料有多少？需要联网补多少？
  policy: 政策文件有几份？（政策驱动型行业的关键项）
  sop: 覆盖了哪些业务领域？缺失哪些？
  competitors_<组>: 各竞品分组资料量如何？是否有完整方案？
  self_<产品>: company.yaml 各产品——源码可达？PRD 已生成？materials 资料完整？
}
```

覆盖度低于 60% 的维度，在《待确认事项》登记并提示用户补充资料。
