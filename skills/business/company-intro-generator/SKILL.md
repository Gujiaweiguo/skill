# Company Intro Generator — 公司介绍与供应商入围方案 Agent Pipeline

## DocSpec 质量基线

本 skill 生成的公司介绍、客户方案、功能响应表、PPT/Word 内容包必须遵守 `/opt/code/skill/references/docspec/`，重点执行 `DocSpec-通用文档质量规范.md`、`方案与投标文档质量规范.md`、`PPT与Word内容包质量规范.md` 和 `文档验收清单.md`。案例、资质、产品能力和客户资产组合路由必须保留证据与边界。

基于 `需求解析 + 标签匹配检索 + 智能编排 + 模板输出` 的方案，支持三种业务模式。

## ⚡ 快速选型：用户说"做方案"时先走这个决策树

**当用户说"做方案"、"出 PPT"、"给 XX 客户做材料"时，Agent 必须先分析客户情况，主动推荐模板，不要等用户自己选。**

### 选型决策树

```
用户说"做方案"
    ↓
Agent 先问/提取 4 个关键信息：
    ① 客户接触阶段（初次/续访/入围招标）
    ② 有没有客户需求文档（Excel/Word）
    ③ 客户组织特征（岗位清晰？多业态？多项目？）
    ④ 决策层背景（是否体系内出身？技术敏感？）
    ↓
按下方矩阵推荐，用 question 工具让用户确认
```

### 模板总览（5 大模式 + E 下 5 个子版本）

| # | 模式 | 一句话特点 | 适用场景 | 页数 | 输出 |
|---|---|---|---|---|---|
| **A** | 初次介绍 | 素材库匹配+模板填充 | 客户初次接触，无需求文档 | 20-40 | 公司介绍 PPT/Word |
| **B** | 供应商入围 | 需求逐条响应+标准报价 | 客户给了功能需求 Excel/Word | 14 | 方案建议书 PPT + 响应表 + 报价单 |
| **C** | 客户资产组合路由 | 按客户已有系统路由 4 版本 | 首访材料准备，按商管/会员组合 | 各 1200 字 | 4 个版本 Markdown 公司简介 |
| **D** | 领导转发简版 | 11 页让领导 3 分钟看懂 | 经办人可能转给决策层 | 11 | AI 岗位增强简版 PPT |
| **E** | 续访兑现承诺 | **续访场景，5 个子版本按客户特征选** | 客户已接触过，本次续访 | 14-48 | 主 PPT + 配套交付物 |

### E 模式子版本选型（续访场景必选一个）

| 子版本 | 一句话特点 | 适用客户 | 页数 | 核心差异 |
|---|---|---|---|---|
| **V1** 卖软件 | 传统软件功能介绍 | 客户纯软件采购视角，只比功能 | 14 | 直接卖功能模块 |
| **V2** 卖结果 | 三层架构+赠送策略 | 客户对传统软件免疫，嫌贵 | 16 | 底座订阅+Skill 赠送+Ops 赠送 |
| **V3** 5 段逻辑链 | 递进式叙事 | 客户技术敏感，要看产品深度 | 21 | 需求→蓝图→具体→超出→落地 |
| **V4** 岗位架构 | 按客户岗位切 | 客户组织岗位清晰，多岗位代表在场 | 17 | 6 岗位各 1 页，底座+Skill 双层 |
| **V5** 领域驱动 | 按业务领域切，YAML 零代码 | **客户多项目多业态，决策层对业务深度敏感** | 48 | N 领域各 1 页，引用 PRD 领域模型 |

### E 模式子版本选择信号（Agent 自动判断）

| 客户特征信号 | → 推荐 |
|---|---|
| 纯软件采购视角，只比功能模块 | V1 |
| 对传统软件免疫，说"系统都差不多" | V2 |
| 决策层中海/万达/印力出身，见过失败案例 | V2 或 V5 |
| 技术敏感（IT 兼职），要看产品深度 | V3 |
| 组织岗位清晰（招商/营运/企划/物业/财务齐全） | V4 |
| 多岗位代表都会参会 | V4 |
| **多项目多业态（3+ 项目，业态不同）** | **V5** |
| **决策层对业务深度极敏感** | **V5** |
| **MI 工程领域架构包已建立** | **V5** |
| 客户组织岗位不清晰或一人多岗 | V5 |
| 客户规模很小（单项目） | V1 或 V3 |

## 配置读取

设置 `LANLNK_BASE` 环境变量指向素材根目录（默认当前目录），然后读取项目配置：
```yaml
# 路径: config/lanlnk.yaml（相对于 skill 根目录）
```

设置以下变量（后续所有路径引用均使用）：
- `$MATERIALS_DIR` = `$LANLNK_BASE/materials`
- `$PROPOSALS_DIR` = `$LANLNK_BASE/out/proposals`
- `$BIDDING_DIR` = `$LANLNK_BASE/out/bidding`

## 素材库结构

素材库位于 `$MATERIALS_DIR`，按类型分为 7 大类：

```
materials/
├── 01-company-overview/      公司概况（简介、历程、组织架构、业绩）
├── 02-qualifications/        资质证照（ISO、高新、软著、奖项）
├── 03-products/              产品方案（定位、功能、架构、优势）
├── 04-cases/                 客户案例（独立文件 + 带链接索引汇总）
├── 05-implementation/        实施方法论（实施流程、项目管理、培训）
├── 06-services/              服务体系（SLA、运维服务、数据安全）
├── 07-personnel/             项目人员（团队架构 + 个人档案）
└── raw/                      原始文档转换后的 Markdown（只读）
```

所有素材文件格式为 Markdown + YAML frontmatter，包含 id/type/domain/industry/scenario/tags 检索标签。

### 案例文件规范

案例已拆分为独立文件，每个案例包含 6 模块：
1. 项目背景 → 2. 需求分析 → 3. 实现功能 → 4. 实现效果 → 5. 项目图片 → 6. 合同信息

案例索引见 `$MATERIALS_DIR/04-cases/服务客户案例汇总.md`，按行业分类标注完整度。

### 人员文件规范

团队架构见 `$MATERIALS_DIR/07-personnel/项目团队架构.md`，
每个角色独立文件，含基本信息、职责、项目经验、证书、社保。部分人员姓名待补充。

### 5 种匹配级别

当素材满足以下条件时自动匹配：
- **精准匹配**：domain 标签完全匹配用户业务线 → 最高优先级
- **行业匹配**：industry 匹配 → 优先展示
- **场景匹配**：scenario/tags 匹配 → 补充展示
- **业务线扩展**：实施方法论/服务体系默认匹配所有业务线
- **兜底**：公司概况 + 资质 + 团队 → 必选

### 0.2 模式A：从需求提取参数

| 参数 | 说明 | 示例 |
|-----|------|------|
| 业务线 | 目标产品/方案领域 | 商管、会员、AI客服、AI问数、全栈 |
| 行业 | 目标客户行业 | 商业地产、零售、金融、政务 |
| 场景 | 业务场景 | 数字化转型、会员营销、私域运营 |
| 格式 | 输出格式 | Word、PPT |
| 篇幅 | 内容详细程度 | 简要版、标准版、详细版 |

### 0.3 模式B：解析客户需求文档

当用户提供需求文档（通常是 Excel）时，按以下步骤解析：

**步骤1：读取需求文档**
```bash
# Excel 格式 — 用 openpyxl 读取
python3 -c "
import openpyxl
wb = openpyxl.load_workbook('需求文档.xlsx', data_only=True)
for name in wb.sheetnames:
    ws = wb[name]
    for row in ws.iter_rows(values_only=True):
        print(' | '.join([str(v)[:80] if v else '' for v in row]))
"
```

**步骤2：提取需求条目**

将客户需求文档解析为标准化结构：
```
需求条目 = {
  序号: int,
  终端: "CRM后台 | 小程序 | APP",
  主模块: "会员管理 | 积分 | 营销 | 停车 | 活动 | ...",
  次模块: "具体功能名称",
  功能说明: "详细描述",
  匹配状态: "完全满足 | 部分满足 | 需定制 | 不支持"  ← P1阶段填充
}
```

**步骤3：提取关键参数**

从需求文档中推断：
| 参数 | 来源 |
|------|------|
| 客户名称 | 文件名或文档标题 |
| 业务线 | 根据需求内容判断（会员/商管/AI等） |
| 行业 | 根据客户背景判断 |
| 规模 | 根据需求中的商圈数、项目数判断 |
| 部署方式 | SAAS 或 私有化（根据需求或客户偏好） |
| 报价口径 | 首项目 + 新增项目数量 |

### 0.4 环境检测

1. 读取至少一份匹配素材 → 继续
2. 素材引用完整 → 内容包可生成
3. [模式B] 客户需求文档可读取 → 功能响应可生成

### 0.5 模式C：客户资产组合路由（对齐战略 v7）

**前置依赖**：先读取战略总报告路线定义
`$LANLNK_BASE/out/strategy/商业地产信息化战略/output/战略分析总报告.md` §1.2.1 两条路线。

**战略路线口径**（v7）：
- **B 路线（主战场）**：中腰部客户，已有商管/会员/POS/停车等系统 → "不换系统，用 AI 把已有系统用起来，降本、提效、增收"
- **D 路线（样板验证）**：低端/中小项目，无系统或系统弱 → "不是上一套传统系统，而是上 AI+商管/会员底座，让老板直接看到经营结果"

**4 版本路由表**（按客户"商管 / 会员"的有×无组合）：

| 版本 | 客户已有系统 | 战略路线 | 推荐产品组合 | 一句话卖点 |
|------|------------|---------|-------------|-----------|
| **V1** | 商管 ✓ + 会员 ✓ | B 路线 | 建议先验证：AI 激活已有商管与会员系统 | 不换系统，用 AI 把已有系统"用起来"，先选1-2个岗位场景验证 |
| **V2** | 商管 ✗ + 会员 ✓ | B 路线延伸 | 建议先验证：老板实时看到经营状况 | 先补齐关键经营数据，让老板能问数、看日报、追异常 |
| **V3** | 商管 ✓ + 会员 ✗ | B 路线延伸 | 建议先验证：会员资产沉淀与活动复盘闭环 | 参考正祥立项逻辑，先把停车、券、活动和会员身份打通 |
| **V4** | 商管 ✗ + 会员 ✗ | D 路线 | 建议先验证：轻量经营底座 + 一个 AI 经营样板 | 从一个经营问题开始，让老板先看到经营结果 |

**关键产品素材引用**：

| 产品 | 素材路径 | 用于版本 |
|------|---------|---------|
| 商业地产 AI Skills 增强服务（= LnkAgent 岗位 Skill 平台） | `$MATERIALS_DIR/03-products/商业地产AISkills增强服务.md` | V1-V4 全部 |
| 商管 ERP 系统（ShopEM） | `$MATERIALS_DIR/03-products/商管ERP系统.md` | V2、V4 |
| 商圈会员 CRM 系统 | `$MATERIALS_DIR/03-products/商圈会员CRM系统.md` | V3、V4 |
| 岗位 Skill 详细方案（营运/客服/招商/账龄/工单/企划） | `$CREAISKILL_BASE/04_岗位解决方案/*.md` | V1-V4 按 P0 主备选取 |

**AI 岗位 Skill 首访裁剪原则**：
- 4 个版本底层能力可以完整保留，但首访材料只呈现与客户现状最相关的 1-2 个验证场景。
- 联系人转领导场景下，PPT 必须让领导 3 分钟内看懂：不替换现有系统、解决岗位生产力问题、建议 30-60 天试点。
- 领导转发简版必须保留一页标杆客户 Logo 墙，建议标题为"蓝联服务过的商业地产与流通标杆客户"，放在"蓝联做什么"之后作为背书。
- 完整能力清单可放在后续方案或附录，不在首访前 5 页展开。

## P1: 素材检索与匹配

### 1.1 模式A：标签匹配

使用语义检索 + 标签匹配，按以下优先级筛选：

### 2.0 心理触发 + 咨询式写作原则

所有对外公司介绍先服务目标动作，而不是先介绍蓝联。生成前必须明确：读者看完后希望做什么。

| 目标动作 | 写作重点 |
|---|---|
| 经办人愿意转发 | 降低转发风险，给出转发理由和可复制话术 |
| 领导愿意见面 | 让领导看到经营价值、低风险试点和清晰下一步 |
| 客户愿意调研 | 让客户认同症状，愿意开放信息 |
| 客户愿意立项 | 证明问题值得解决，且可用小场景验证 |

领导转发简版使用固定说服链：

```text
目标动作 -> 读者心理 -> 趋势/危机 -> 症状假设 -> 未来收益 -> 蓝联解决路径 -> 蓝联可信证明 -> 低风险下一步
```

心理触发必须覆盖多类读者：

| 类型 | 心理驱动 | 材料触发方式 |
|---|---|---|
| 跟随型 | 怕落后、怕同行已做 | 行业趋势、同业动作、危机感 |
| 领先型 | 想创新、想做样板 | 政策号召、技术成熟、可见效果 |
| 风险规避型 | 怕项目失败、怕影响现有系统 | 只读接入、小范围试点、本地部署、人工兜底 |
| 结果导向型 | 只关心值不值得 | 经营指标、节省时间、异常发现、ROI验证 |

买药与保健品逻辑：

- 买药：先提出客户可能认同的症状，再给解决路径。例：领导问数慢、报表人工重、活动复盘难、客服咨询重复、数据分散。
- 保健品：激发更好状态的向往。例：领导随时看经营、已有系统价值放大、形成AI应用样板、岗位少做重复劳动。

咨询式页面规则：

- 标题必须是判断句，不写泛泛的“产品介绍”“公司简介”。
- 每页只传达一个核心观点。
- 先给结论，再给分解和证据。
- 用“我们对贵司这类客户的假设”表达症状，避免未经验证地诊断客户。
- 心理触发、买药、保健品、跟随型、领先型、经办人转领导等词只用于内部创作判断，严禁出现在对外PPT正文和文件名里。

蓝联可信证明必须形成四段链条：

| 证明类型 | 推荐页面 |
|---|---|
| 行业证明 | 标杆客户Logo墙 |
| 场景证明 | 岗位Skill全景和重点场景 |
| 系统证明 | 底层已有系统 + 中层岗位Skill + 上层运营服务三层图 |
| 交付证明 | 30-60天试点路径和风险控制 |

广州海港城这类“已有商管 + 会员系统，联系人转领导”场景，PPT建议结构：

```text
P1 封面：不换系统，用AI让已有商管与会员系统产生经营结果
P2 为什么值得转给领导
P3 行业趋势与危机感
P4 我们对已有商管+会员客户的症状假设
P5 领先型客户能看到什么效果
P6 蓝联做什么
P7 标杆客户Logo墙
P8 岗位Skill全景
P9 第一期建议做什么
P10 30-60天怎么验证
P11 为什么风险可控
P12 下一步只约30分钟
```

## P2.8 模式E：续访兑现承诺（首次沉淀：2026-07-25 佛山若有光商业 case）

**适用场景**：客户已经接触过（一访/二访），上次承诺了某事（如"开发完给看"、"做完给反馈"），本次是续访。**核心目标不是销售，是让中间决策人（如副总/部门负责人）敢跟最终决策人（如总经理）说"这家能上"**。

**与 A/B/C/D 的根本区别**：
- A 初次介绍：纯销售
- B 供应商入围：客户给了需求文档
- C 客户资产组合路由：4 个版本路由
- D 领导转发简版：经办人转领导首访材料
- **E 续访兑现承诺**：续访 + 兑现承诺 + 让中间人向决策人转述

### E.1 触发条件（强信号）

- 客户上次明确说"X 完成后给看"、"做完通知我们"、"开发完再聊"
- 客户经理主动约（不是客户主动问）
- 上次接触时蓝联处于"开发中/未交付"状态，本次状态有重大进展
- 客户内部存在中间决策人（副总/部门负责人）和最终决策人（总经理/老板）两层

### E.2 PPT 结构（基于 2026-07-25 佛山若有光商业 case 沉淀）

**核心原则**：透明展示真实进度（不吹、不藏），让客户敢拍胸脯向领导汇报。

**标准 14 页结构**：

```
P1   封面（客户名 + 方案主题 + 日期）
P2   【关键】上次见面回顾 + 这 X 周/月我们的进展       ← 兑现承诺，必须放 P2
P3   我们对客户业务的理解（项目/业态图谱）              ← 证明你懂他
P4   决策层（最终拍板人）的核心痛点解码                  ← 用"假设"语气，不直接诊断
P5   竞品/行业对比：为什么传统方案解决不了              ← 给中间人向决策人汇报的弹药
P6   蓝联的设计哲学/差异化                              ← 不堆功能，讲思路
P7   【关键】产品真实成熟度透明展示                     ← 哪些能用、哪些验收中、哪些 blocked
P8   【可选】客户旗舰项目/标杆场景的专题页              ← 证明认真准备了
P9   差异化配置方案（一页大表/时间线）                  ← 真懂业务
P10  关联产品（如会员系统、AI 能力等）                  ← 不主推，作为组合补充
P11  数据驾驶舱/价值可视化                              ← 给决策层"5 分钟看清全局"的样子
P12  实施路径与时间表（按项目/阶段分期）
P13  下一步建议（30-60 天小场景验证，低风险）
P14  Q&A
```

### E.3 写作铁律（基于销售方法论 + 本次实战）

| 铁律 | 说明 |
|---|---|
| **P2 必须是"兑现承诺"** | 不写公司介绍开场，第一页就讲"上次承诺的事，我们做到了 X%" |
| **透明展示真实进度** | 区分"已生产就绪/已交付未验收/blocked"，不吹"全部完成"。客户决策层一眼识破吹牛 |
| **价格落预算区间** | 客户上次的预算锚点必须尊重（如"10 万/年"），首年含实施落在区间内 |
| **不要现场逼单** | 本次目标是"敢转告"，不是"现场签约"。**留谈判空间给中间人** |
| **不直接诊断客户** | 用"我猜/我们假设/我们对贵司这类客户的理解"语气 |
| **竞品不点名攻击** | 用"市面典型方案/其他主流方案"，不说"凯捷/明源不行" |
| **决策层不在场也要为他写** | 中间人（如副总）需要的是"敢拍胸脯的料"，不是技术细节 |

### E.4 必备附件（不只是 PPT）

模式 E 的核心交付物 **不止 PPT**，必须配套产出：

| 附件 | 用途 | 篇幅 |
|---|---|---|
| **主 PPT**（14 页） | 会议主讲 | 30-40 页（含复用的公司案例段） |
| **决策层汇报单页话术**（A4 一页） | 给中间人转述决策层用，**不是给决策层本人看** | 1 页 3 段 |
| **演示前数据清理建议**（如果涉及 demo） | 给客户经理，避免演示穿帮 | 详细到文件路径和 SQL |
| **会议话术 checklist**（分时段） | 给客户经理，2 小时怎么用 | 120 分钟分段 |
| **关联产品/能力的单页**（可选） | 锦上添花，不冲淡主方案 | 1 页 A4 |

### E.5 模式 E 的 5 个高风险点（基于本次实战）

| 风险 | 应对 |
|---|---|
| **决策层背景敏感**（如中海/万达体系出身） | 数据规范判断标准极严，演示数据必须清理干净 |
| **产品还在开发** | 透明分层表达：核心模块 production-ready / 新增功能验收中 / blocked 项明确说 |
| **客户预算有锚点** | 价格策略必须落到锚点区间，**反向把"贵"转化为"值"**（如别家 40 万一次性 vs 我们 SaaS 12 万/年） |
| **多项目多业态** | 强调"一套底层 + N 套配置"，不要套用单一业态模板 |
| **客户决策链有中间人** | 给中间人准备好"汇报话术单页"，让他能转述，不要只给他技术 PPT |

### E.6 PPT 生成路径（与现有 proposal-pptx compile.py 兼容）

**YAML 内容包示例**（参考 2026-07-25 case）：

**关键约束**：
- 第 1 个 section 必须包含 P2"上次进展"（type: text-bullets）
- 必须有 1 页用 type: requirement-understanding 表达"对客户业务的理解"

### E.9 案例：2026-07-25 佛山若有光商业

**背景**：
- 客户：佛山若有光商业（5 个轻资产项目：盐步老龙1432/光之水岸/奇遇里Alice Market/金沙水街/紫泉会馆）
- 上次接触：田总（总经理，中海环宇城出身）+ 邹总（企划+信息化）
- 上次承诺：MI 开发完给看
- 客户预算锚点：10 万/年（别家 40 万一次性被拒）
- 本次会议：邹总单独见，2 小时深入聊

**产出**：
- 32 页主 PPT（基于正祥选型方案模板）
- 02_Content OS 单页（给邹总企划岗的礼物）
- 03_邹总向田总汇报话术（A4 一页 3 段）
- 04_MI demo 数据清理建议（含 SQL 和文件路径）
- 05_会议话术 checklist（120 分钟分 8 段）

**关键经验**：
1. **决策层背景调研是关键**：田健中海体系出身 → 对数据规范极严 → 必须演示前清掉 535.7% 收缴率 bug
2. **多项目多业态是差异化金矿**：传统商管系统都是为购物中心设计，5 个非标项目只有蓝联能适配
3. **价格锚点必须尊重**：客户上次的预算数字（10 万/年）是硬约束，方案必须落进去
4. **附加能力（如 Content OS）要克制**：作为附件单页，不在主 PPT 展开，避免冲淡焦点
5. **"汇报话术单页"是隐藏高价值交付**：让中间人能转述，比给他 100 页 PPT 更有用

### E.10 价值主张重构（V2 进阶子模式）

**触发场景**：续访兑现承诺过程中，客户经理发现**单纯"卖软件"无法打动客户**（如客户对传统软件免疫、客户决策层是体系内出身见过太多软件、客户预算敏感不愿为软件付费）。此时**主动重构价值主张**：从"卖软件功能"升级为"卖经营结果"。

**V2 核心策略（2026-07-25 佛山若有光商业 V2 实战）**：

```
旧方向（V1）：卖 MI 商管 + 会员系统
   ↓ 价值主张重构
新方向（V2）：卖 LangChat 岗位 Skill + 底座配套
```

**V2 三层架构**（必须画在 PPT 上）：

| 层级 | 内容 | 收费逻辑 |
|---|---|---|
| ③ AgentOps 持续运营层 | 周复盘/效果看板/知识更新/SLA/客户成功 | **赠送**（价值约 20 万/年）|
| ② LangChat 岗位 Skill 层 | 营运/客服/招商/财务/工程/企划/智能问数 7 个 Skill | **赠送**（价值约 30 万/年）|
| ① 系统底座 | 蓝联 MI 商管 + 会员 CRM + 客流/车流/财务/HR/OA/POS/停车/工单 | **极低订阅收费** |

**V2 五大金句**（必须出现在 PPT 和话术中）：

1. **"蓝联不是又一套商管软件，是商业地产 AI 经营结果服务商"**
2. **"底座订阅收费 + 岗位 Skill 赠送 + AgentOps 赠送，为结果负责"**
3. **"MI 规划的所有功能都会免费在后续迭代中给客户，不限模块"**
4. **"传统软件卖功能，蓝联卖'田总每天 5 分钟看清 5 个项目'这个结果"**
5. **"蓝联自己就在用——官网 11 篇文章 7 篇 AI 写，吃自己狗粮"**

**V2 价格策略（必杀技）**：

```
【收费】底座订阅：5 项目打包首年 12-15 万，次年 8-10 万
【赠送】LangChat 岗位 Skill：7 个 Skill 全部免费使用权（价值约 30 万/年）
【赠送】AgentOps 持续运营：周复盘/效果看板/知识更新（价值约 20 万/年）
【续费逻辑】客户见到效果后续费扩展，蓝联始终为结果负责
【最低保障】即使只用底座，蓝联的"底座+订阅+免费迭代"已胜过任何竞对
```

**V2 vs V1 关键差异**：

| 维度 | V1（卖软件） | V2（卖结果） |
|---|---|---|
| 主推产品 | MI 商管+会员系统 | LangChat 岗位 Skill 平台（底座配套）|
| 价值主张 | 我们功能强大 | 我们为结果负责 |

### E.11 V3 五段式逻辑重构（2026-07-25 佛山若有光商业 V3 案例）

**V2 的问题**：虽然价值主张对齐了"为结果负责"，但 PPT 仍是 16 页功能罗列，**缺乏叙事逻辑链**——客户看完不知道蓝联具体怎么解决他的问题。

**V3 核心升级**：把 PPT 重构为 **5 段式逻辑链**，每页回答"这一页对客户的价值是什么"。

**V3 五段式结构**：

```
① 客户需求理解（5 页）
   ↓ "你们真正需要的是..."
② 蓝联方案蓝图（2 页）
   ↓ "蓝联三层架构是什么"
③ 具体方案详细展开（8 页，含产品核心功能 each 1 页）
   ↓ "MI/CRM 怎么一一解决你的需求"
④ 超出预期（3 页）
   ↓ "岗位 Skill = AI 助手，AgentOps = 定期升级"
⑤ 落地（3 页）
   → "价格策略 + 实施路径 + 试点方案"
```

**V3 vs V2 关键差异**：

| 维度 | V2 | V3 |
|---|---|---|
| PPT 逻辑 | 16 页功能罗列 | **5 段式逻辑链**（21 页）|
| 产品功能 | 1 页带过 | **核心功能 each 1 页详细展开**（如 MI 的资源/合同/财务/ChatBI 各 1 页）|
| 叙事连贯性 | 跳跃式 | **递进式**（需求→蓝图→具体→超出→落地）|

**V3 必备页面（21 页结构）**：

```
Section 1：客户需求理解（5 页）
- P1 上次进展（兑现承诺）
- P2 客户业务画像（项目/业态图谱）
- P3 决策层核心需求（如"老板三问"）
- P4 多项目管控具体痛点
- P5 需求解码（引出方案）

Section 2：蓝联解决方案（16 页）
【2.1 蓝图】2 页
- 三层架构图（产品蓝图）
- 与传统软件对比

【2.2 具体方案详细展开】8 页（核心变化）
- 底座解决决策层需求（总览，明确对应关系）
- 产品核心功能①详细展开（如：资源管理）
- 产品核心功能②详细展开（如：合同管理）
- 产品核心功能③详细展开（如：财务管理）
- 产品核心功能④详细展开（如：ChatBI/智能问数）
- 产品真实状态透明展示
- 多项目差异化配置
- 关联产品（如会员系统）一页带过

【2.3 超出预期】3 页
- 岗位 Skill = 给岗位配 AI 助手（类比：永远不休息的助理）
- AgentOps = 给 AI 助手定期升级（类比：手机系统升级）
- 决策层最终画面（如：驾驶舱截图）

【2.4 落地】3 页
- 价格策略（底座订阅+赠送）
- 实施路径
- 试点方案
```

**V3 写作铁律（在 V2 基础上增加）**：

| 铁律 | 说明 |
|---|---|
| **每页回答客户价值** | 不写"产品介绍""功能说明"，写"这一页解决客户什么问题" |
| **核心功能 each 1 页** | 不能用 1 页带过，每个核心功能单独展开讲清楚怎么解决需求 |
| **明确需求-方案对应关系** | 在总览页明确"功能①解决需求①、功能②解决需求②" |
| **超出预期用类比** | "AI 助手"比"岗位 Skill"更易懂，"定期升级"比"持续运营"更具体 |
| **逻辑链不断裂** | 5 段之间用过渡句衔接，让客户感受到递进 |

**V3 识别信号（什么时候用 V3 而非 V2）**：

| 信号 | 切换到 V3 |
|---|---|
| 客户决策层是体系内出身（中海/万达/印力）| ✅ 必须 V3，要看具体功能 |
| 客户技术敏感（如 IT 兼职）| ✅ 建议 V3，要让 IT 看到产品深度 |
| 客户问"具体怎么解决" | ✅ 必须 V3，1 页带过会失去信任 |
| 客户预算紧 | ⚠️ V2 即可，V3 篇幅长可能超时 |
| 客户只看价格 | ⚠️ V2 即可，V3 浪费时间 |
| 客户规模很小（单项目）| ❌ 用 V1 |

### E.12 V4 岗位架构模式（2026-07-25 佛山若有光商业 V4 案例）

**V3 的问题**：5 段式逻辑清晰，但仍以"产品功能"为中心展开（MI 4 核心功能 each 1 页），客户看完仍不知道"我的岗位具体怎么解决"。口吻多次出现"田总""邹总"，针对个人而非面向公司。

**V4 核心升级**：以**客户岗位**为中心重构叙事。每个岗位 1 页详细展开"2 层方案"——传统系统底座如何满足功能 + 岗位 Skill 如何超预期降本提效。

**V4 vs V3 关键差异**：

| 维度 | V3 | V4 |
|---|---|---|
| 叙事中心 | 产品功能（MI 4 核心）| **客户岗位**（6 岗位 × 2 层方案）|
| 口吻 | "田总""邹总" | **面向公司**（"总经理岗位""贵司"）|
| 解决方案展开 | MI 资源/合同/财务/ChatBI 各 1 页 | **6 岗位 each 1 页**（底座满足+Skill 超预期）|
| 蓝图页 | 三层架构图 | **2 层方案**（底座满足+Skill 超预期）|
| 公司介绍 | 散落 | **独立 P5**（关于蓝联，与项目无关）|
| 总页数 | 44 页 | **38 页**（更紧凑）|

**V4 标准结构（17 页自定义）**：

```
Section 1：对客户需求的理解（4-5 页）

### E.13 V5 领域驱动方案模式（2026-07-27 佛山若有光商业 V8b case 沉淀）

**V5 vs V4 根本区别**：

**V5 与 V4 的关系决策**（对齐用户共识）：

| 客户特征 | 推荐模式 | 切法 |

| 多业态/多项目/业务领域复杂 | **V5 领域驱动** | 按领域切，每领域 1 页 |

### E.13.1 触发条件

- 客户明确按业务条线管理（如招商线/财务线/营运线分头汇报）

### E.13.2 V5 五段结构（48 页 = 24 自定义 + base PPT 复用段）

```
① 公司介绍+案例段（base PPT 复用，约 20 页）

### E.13.9 V5 案例：2026-07-27 佛山若有光商业

**背景**：
- 客户：佛山若有光商业（5 个轻资产项目）
- 决策层：田总（总经理，中海体系出身）—— 对业务深度极敏感
- 中间人：邹总（企划+信息化）
- 上次承诺：MI 开发完给看

**为什么用 V5 而非 V4**：
- 5 个项目业态完全不同（文旅/滨水/街区/公园/社区），按岗位切无法体现业态差异
- 田总中海体系出身，需要看到每个业务领域的具体能力深度
- MI 工程领域架构包已建立（领域模型主文件齐全）

- 48 页主 PPT（24 自定义 + base PPT 复用段）

- 配套交付物 6 件（03/04/05/06/07 + V8b PPT）

**关键经验**：
1. **领域驱动比岗位驱动更适合多业态客户**——按领域切能覆盖所有业态的业务差异
2. **so_what 右栏是 V5 的灵魂**——每页必须有 3 条价值结论，不是功能罗列
3. **6+ 种视觉模式防止审美疲劳**——每领域页用不同 visual（schematic/big_number/lifecycle/comparison/funnel/loop）
4. **YAML 配置可复用**——换客户只需改客户信息+领域列表，视觉组件全复用
5. **领域数控制在 5-15 个**——太少不够丰富，太多超过 15 页客户疲劳

## P3: 文档生成

### 3.1 生成策略

#### PPT 三路径决策树（先判断，再生成）

生成 PPT 前，**先判断走哪条路径**，避免无谓的定制工作：

| 路径 | 触发条件 | 做法 | 适用场景 |
|------|---------|------|---------|
| **路径 1：直接复用** | 客户需求场景与参考 PPT 主题（商圈会员CRM）完全契合，且目标案例已在参考 PPT 13 家覆盖清单中 | `cp` 参考 PPT → 用 python-pptx 改封面副标题/日期 → 检查目录页一致性 | "会员系统公司介绍"、"商圈CRM 方案介绍" |
| **路径 2：复用 + 插入定制页** | 主体契合，但有 1-3 页客户专属内容（痛点/合作建议/新案例） | 路径 1 + 用 python-pptx 在合适位置插入定制页 | 大多数模式 A 场景 |
| **路径 3：compile.py 全量编译** | 需要大量定制（模式 B 供应商入围、方案建议书、功能响应表/报价） | 输出 YAML 内容包 → 调用 proposal-pptx compile.py | 模式 B、跨主题方案 |

**判断口诀**：先查参考 PPT 页码索引（`references/reference-ppt-index.md`），如果客户需求 80%+ 已被参考 PPT 覆盖，走路径 1 或 2；否则走路径 3。

**路径 1 最小操作示例**（直接复用改封面）：
```python
from pptx import Presentation
from shutil import copy as copy_file

# 1. 复制参考 PPT 到目标位置
copy_file(reference_ppt, target_path)

# 2. 用 python-pptx 改封面文字
prs = Presentation(target_path)
cover = prs.slides[0]
# 找到副标题 shape，改文字
cover.shapes[1].text_frame.paragraphs[0].runs[0].text = "{客户名}方案汇报"
# 找到日期 shape，改文字
cover.shapes[2].text_frame.paragraphs[0].runs[0].text = "{YYYY.MM}"
prs.save(target_path)

# 3. 检查目录页一致性（见 references/troubleshooting.md）
```

#### 各输出格式对应的生成方式

根据输出格式选择生成方式：

| 输出格式 | 生成方式 | 适用模式 |
|---------|---------|---------|
| PPT（.pptx） | **输出 YAML 内容包 → 调用 proposal-pptx compile.py（模式A用 mode=intro，模式B用 mode=proposal）** | A+B |
| Word（.docx） | **输出结构化 Word 内容包 → 调用 word-master 进行排版** | A+B |
| 报价单（.xlsx） | **openpyxl 按标准格式生成** | B |
| 功能响应表（.xlsx） | **openpyxl 按标准格式生成** | B |
| Markdown | 直接输出草稿 | A+B |

### 3.2 PPT 生成：输出 YAML 内容包 → proposal-pptx 模板编译器

**公司介绍/方案建议书 PPT 使用 proposal-pptx 模板编译器。** 模式 A（初次介绍）用 `mode=intro`，模式 B（供应商入围）用 `mode=proposal`。基于蓝联标准参考 PPT（62页，含真实产品截图+案例图），复用公司介绍+案例 section，插入客户定制页，输出统一 3 母版风格的高质量 PPT。

**流程：**
1. P2 内容编排完成后，生成 YAML 内容包 `{项目名称}_intro-pptx.yaml`
2. 放入 `$PROPOSALS_DIR/content-packages/`
3. 执行编译：
   ```bash
   cd $SKILL_DIR/skills/ppt/ppt-master/templates/proposal-pptx
   uv run compile.py "$PROPOSALS_DIR/content-packages/{项目名称}_intro-pptx.yaml"
   ```
4. 输出到 `$PROPOSALS_DIR/{项目名称}/蓝联科技公司介绍_{客户简称}_{YYYYMMDD}.pptx`

**YAML 内容包结构（intro 模式）：**

```yaml
mode: intro
base_ppt: "/opt/code/docs/lanlnk/incoming/正祥选型方案/蓝联科技CRM商圈会员数智营销方案_202604.pptx"
output: "$PROPOSALS_DIR/{项目名称}/蓝联科技公司介绍_{客户简称}_{YYYYMMDD}.pptx"

cover:
  subtitle: "{客户全称}"
  date: "{YYYY年M月}"

toc:
  titles:           # 目录页标题（4项以内）
    - 关于蓝联
    - "{定制章节1}"
    - "{定制章节2}"
    - 合作展望

theme:
  primary: "#0A1F3D"
  accent: "#2196F3"
  font: "Microsoft YaHei"

slides:              # 客户定制页（插在公司介绍+案例之后）
  - type: text-bullets
    title: "{标题}"
    body: "{正文}"
    items: ["要点1", "要点2"]
  - type: feature-cards
    title: "{标题}"
    columns: 3
    items:
      - title: "{卡片标题}"
        body: "{卡片描述}"
```

**可用 slide 类型：**
- `text-bullets` — 标题+正文+要点列表
- `feature-cards` — 标题+卡片网格（columns: 2/3/4）

**输出结构（intro 模式）**：
- P01 封面（参考 PPT P01，母版=标题幻灯片）
- P02 目录（参考 PPT P02，母版=节标题，文本已修改）
- P03-P20 客户定制页（YAML slides，母版=标题和内容）
- P(N+1) 为什么选择蓝联（参考 PPT P36）
- P(N+2) 感谢观看（参考 PPT P62，母版=标题幻灯片）

> **注意**：参考 PPT 的公司简介+案例段实际在 **P38-P55**（不是 P03-P20），完整页码索引见 `references/reference-ppt-index.md`。compile.py 会自动选取参考 PPT 中需要的段落拼接，YAML 编写者不需要手动指定页码。

### 3.3 Word 生成：输出结构化 Word 内容包

**不再使用 python-docx 自行生成 Word。** 改为按 [Word 内容包规范](../../word/word-master/reference/word-content-package-spec.md) 输出 `.word-content.md`，交给 word-master 做专业排版。

**流程：**
1. P2 内容编排完成后，按 Word 内容包规范生成 `.word-content.md`
2. 放入 `$PROPOSALS_DIR/content-packages/{项目名称}_产品方案书_{YYYYMMDD}.word-content.md`
3. 告知用户："内容已编排完成，正在调用 word-master 排版生成产品方案书..."
4. word-master 读取内容包后自动生成 `.docx`，输出到 `$PROPOSALS_DIR/{项目名称}/`

**公司介绍/方案书章节 → 内容包映射：**

| 文档章节 | 内容包元素 | 说明 |
|---------|-----------|------|
| 封面 | `cover:` 元数据 + `template: proposal` | 公司介绍封面 |
| 目录 | 自动生成 | word-master 根据 heading-1 生成 |
| 公司简介 | `heading-1` + 正文 + 配图引用 | 分页 |
| 行业洞察 | `heading-1` + bullet list | 分页 |
| 产品方案 | `heading-1` + `heading-2` 每产品一节 | 分页，可选 `table: function-matrix` |
| 实施方法 | `heading-1` + 流程描述 | 分页 |
| 服务体系 | `heading-1` + 服务项目列表 | 分页 |
| 客户案例 | `heading-1` + 每个案例一页 | 分页，含表格 |
| 资质荣誉 | `heading-1` + 资质列表 | 可合并到公司简介 |
| 团队介绍 | `heading-1` + `table: personnel-matrix` | 可选 |
| 联系方式 | `heading-1` | 结尾页，不必须分页 |

### 3.4 输出文件

**模式A（初次介绍）输出：**
- PPT：`$PROPOSALS_DIR/{项目名称}/蓝联科技公司介绍_{客户简称}_{YYYYMMDD}.pptx`
- Word：`$PROPOSALS_DIR/{项目名称}/产品方案书_{项目简称}_{YYYYMMDD}.docx`

**模式B（供应商入围）输出：**
- PPT：`$PROPOSALS_DIR/{项目名称}/方案建议书_{客户简称}_{YYYYMMDD}.pptx`
- 功能响应表：`$PROPOSALS_DIR/{项目名称}/功能响应表_{客户简称}_{YYYYMMDD}.xlsx`
- 报价单：`$PROPOSALS_DIR/{项目名称}/报价单_{部署方式}_{客户简称}_{YYYYMMDD}.xlsx`
- Markdown 草稿：`$PROPOSALS_DIR/{项目名称}/方案建议书_草稿.md`

## 模式B 完整工作流（供应商入围）

```
客户需求文档（Excel/Word）
        ↓
P0: 需求解析（openpyxl 读取 → 提取需求条目 → 推断业务参数）
        ↓
P1: 功能响应匹配（需求 × 产品功能清单 → 逐条匹配 → 功能响应表）
        ↓
P2: 内容编排（需求理解 → 方案概述 → 功能概览 → 架构 → 报价 → 服务 → 案例）
        ↓
P3: 文档生成
    ├── PPT：输出 YAML 内容包 → proposal-pptx compile.py（mode=proposal）→ 方案建议书.pptx
    ├── 功能响应表：openpyxl 生成 .xlsx
    └── 报价单：openpyxl 按标准4分类格式生成 .xlsx
        ↓
P4: 输出核验（覆盖率检查 + 金额校验 + 完整性检查）
```
