# External Owner Follow-up

This skill-repository change defines interfaces and review rules only. It does not modify canonical product records or target repositories.

| Owner area | Follow-up | Required evidence / decision |
|---|---|---|
| Product documentation owners | Confirm each product's canonical ontology and PRD authority references, versions, owner, and release state; resolve proposed or unresolved entries in the skill-side registry through the owning docs workflow. | Owner-confirmed layer references and review decisions; especially lnkcrm proposed ontology/PRD roots and lnkchatbi proposed ontology release state. |
| Product owners | Identify the owner and approval route for initial and incremental ontology change sets for each in-scope product. | Named destination owner and accepted/rejected/deferred decision references. |
| Product reconciliation owners | Choose or confirm product-owned storage/ledger locations for ontology↔PRD, PRD↔code, and ontology↔code records, without treating the shared schemas as authority. | Product-owned reconciliation records with explicit scope, revisions, coverage, findings, and dispositions. |
| Target code repositories | Adopt the handoff and implementation-return contract in each target repository; create and verify local OpenSpec changes and return trace-linked verification evidence. | Repository-local change IDs, source revisions, verification references, and reviewed return records. |
| Product documentation and code owners | Run at least one reviewed end-to-end cycle for a business product and a tool product, including ontology promotion impact reconciliation and false-positive correction handling. | Accepted ontology release, all applicable pairwise records (or explicit unavailable states), and accepted/incomplete implementation returns as appropriate. |

No external owner, authority path, storage location, or approval decision is inferred by this follow-up list.
