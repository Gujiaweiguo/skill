## 1. 一句话定位

**LnkReport = 企业统一数据输出与报表运行时**——看板 / 大屏 / 报表 / 打印模板四类输出，一套 Dataset
底座与渲染语义内核。（v0.3:7，原文引用）

- 补充口径：LNKCRE 是第一个深度业务消费者，租金账单是最先证明商业价值的 Reference Slice（v0.3:7）。
- 面客压缩候选（**推断，待批**）：「一个引擎，管好商场所有数据输出——从经营看板到租金账单打印」。

## 3. 核心能力卖点（8 条，逐条挂出处）

1. **四类输出一套底座**：看板/大屏/报表/打印模板共享数据模型、表达式、参数、权限和渲染 Runtime
   （v0.3:17）；同一 Dataset 按业务场景输出 Web/PDF/Excel/批量 PDF（v0.3:19）；Excel 走语义投影而非
   「渲染 PDF→解析→转 Excel」（v0.3:20，语义投影红线）。
2. **复杂报表排版全链**：参数化查询与导出、多 Sheet（上限 11）、横向分组跟随扩展、循环块/主子表、
   循环表头、交叉表（含角头斜线标签）、钻取、分版分栏（功能清单:110-118、182、195；竞品对比:12）。
3. **专业级固定版式打印（套打）**：mm 绝对定位、背景套打、明细循环/跨页续排/重复表头合计、流式长文本、
   QR/条码/托管图片/签章/水印（功能清单:120-123）；PDF user-space 几何对位验收口径 ≤1mm（v0.3:258），
   实测最大误差 0.088mm（竞品对比:49；口径=PDF user space，物理打印机不在该精度承诺内）。
4. **多格式导出矩阵**：PDF（WeasyPrint 两条线统一）/ styled·流式双模式 XLSX（按规模自动判定，阈值可配）/
   DOCX 表格投影 / PDF 转 PNG ZIP / 模板 JSON 可移植（功能清单:127-128；v0.3:118-123；导出受限构件
   产物前稳定拒绝，竞品对比:52）。
5. **服务化批量渲染 + 可验证产物**：同步 render（护栏 ≤200 页且 ≤30 秒）+ 异步 batch-render；manifest
   页码区间映射是正式契约（解决「3000 页 PDF 里哪几页属于哪个商户」）（v0.3:143-171）；产物 sha256
   留证 + 全链路审计（v0.3:183）。
6. **身份与权限双轨**：经营分析走用户 Token + 行/列权限；业务单据走 Service Token + 授权 Template
   scope，不继承交互用户行列权限但受 tenant isolation/template scope/审计约束（v0.3:173-184）；
   租户隔离模板治理（版本/文件夹/回收站/收藏/标准模板，功能清单:130）。
7. **安全红线内建**：表达式 AST 白名单求值器（对照积木 4 次 RCE 反例）、SQL 参数驱动级绑定、打印素材
   禁外部 URL 加载（SSRF 防护）、渲染端点强制鉴权 + API Key 按模板列表授权（v0.3:199-202、195、201）。
8. **模板资产化与迁移**：Excel/Word 统一导入工作台（分区识别/字段映射/重导入结构 diff/绑定保留，
   功能清单:161-166）；模板导出/导入/另存/分享 token 与撤销（功能清单:127、130-131）；真实租约模板
   端到端验收在档（yuntai_lease_e1：63 租约号三档 delivered + 六失败演练取证，功能清单:137）。

## 4. 差异化（对积木/帆软——竞品对比 canonical 结论）

1. **产品策略总纲**：不以追平积木 24 域或 FineReport 全平台功能数为目标；差异化重点 = **LNKCRE 单据
   产出、受控批量服务、租户/身份边界、可验证产物和消费者集成**；每个后续能力必须有客户需求或
   Reference Slice 证据（竞品对比:106）。
2. **对帆软 FineReport**：差距集中在更成熟统一的类 Excel 设计器与本地打印软件/打印机绑定/静默打印等
   客户端闭环；后者与 LnkReport 冻结的「PDF 优先、无本地静默打印客户端」边界不同，**不转化为缺失项**
   （竞品对比:14、50）。LnkReport 的优势方向是可审计、可集成输出（竞品对比:54）。
3. **对积木报表**：报表域能力名录旧缺口大多已关闭（竞品对比:47；2026-10-01 回传 10 项补齐——定时自动
   保存/三级动态表头/当前页全量聚合/移动端只读 viewer 等，功能清单:176-186）；安全侧以 AST 白名单
   对照积木 4 次 RCE 反例（v0.3:200）。
4. **诚实边界（反面承诺也是卖点）**：不做 FineReport 式本地打印客户端/静默绑定打印机（功能清单:134，
   explicitly-not-do）；不做定时调度与邮件推送——由 LNKCRE/MI Job 与消费者集成承接（功能清单:135；
   v0.3:194 R3「业务流程不进 LnkReport」）。面客表述建议（**推断，待批**）：把「不做的事」讲成
   「与业务系统职责分清、不重复建设」。

## 5. 客户价值与适用叙事场合

### 5.1 客户价值（由 PRD 原则推导，推导过程标注）

- **同一份数据多种输出**（v0.3:19）→ 客户一次建模，看板/报表/账单/批量单据全场景复用（推导自原则四）。
- **输出与业务解耦**（v0.3:18：LnkReport 负责「怎么生成」，业务系统负责「什么时候、为谁、为什么生成」）
  → 集成责任清晰，业务系统不改流程即可获得文档产出能力。
- **可审计产物**（manifest + sha256 + 审计，v0.3:167、183）→ 财务/对账场景的可追溯性。
- **单据几何精度**（PDF user-space ≤1mm 验收口径 + 0.088mm 实测，v0.3:258；竞品对比:49）→ 套打/票据
  场景可信度（对外宣讲口径**推断，待批**，见 §7-2）。

### 5.2 叙事场合建议（**推断，待批**，见 §7-5）

| 场合 | 讲法 |
|---|---|
| 公司介绍（模式 A/E） | 产品矩阵中定位为「数据输出与报表运行时」底座：AI 问数（LnkChatBI）负责洞察对话，LnkReport 负责把数据变成可交付文档 |
| 方案 PPT（模式 B/C/D） | 商管客户方案里的「账单/对账单/经营报表」章节：以租金账单 Reference Slice 全链（v0.3:250-254）作叙事主线；集成架构图里 LnkReport 出现在「文档产出」格，调度归 LNKCRE/MI（v0.3:135） |
| 案例叙事 | G1 真实租约模板验收（63 租约号、三档交付、失败演练取证，功能清单:137）可作交付质量证据；**客户名对外披露待授权**（§7-3） |

## 6. 与其他产品边界（防讲混）

| 产品 | 边界 | 出处 |
|---|---|---|
| **LnkVision** | Vision 是商业物业 AI 视觉巡检告警平台（摄像头→告警/工单/通知），**无报表/打印能力**；LnkReport 不做 AI 视觉检测。两者唯一相邻点是各自都有「看板」，语义不同（Vision 看板=告警运营监控；LnkReport 看板=BI 数据可视化） | Vision 产品PRD:11；Vision 功能清单:29；产品PRD:162-174 |
| **MI（岗位 AI Skill 工作流平台，langchat/OrchestratorAgent 体系）** | MI/LNKCRE 是 LnkReport 的**调度与消费者侧**：定时调度、邮件推送由 LNKCRE/MI Job 与消费者集成承接，LnkReport 只提供服务渲染与任务产物（v0.3:135；功能清单:135）。面客材料中不得把 LnkReport 讲成「AI 工作流平台」或把 MI 讲成「报表引擎」（表述**推断，待批**，§7-6） | v0.3:135、18；功能清单:135 |
| **LnkChatBI** | 问数底座（自然语言→SQL→图表）；且可作为 LnkReport 内嵌 AI SQL 助手端点（/mysqlbot/api）运行——问数出洞察，LnkReport 出文档 | 产品PRD:312-316 |
| **LnkCRE（商管）** | 第一个深度业务消费者（v0.3:7）：合同/账单等业务语义在 LnkCRE，单据产出与打印在 LnkReport | v0.3:7、18、250-254 |
