## 1. 一句话定位

**LnkVision 是商业物业的 AI 视觉巡检告警平台**：从摄像头截图中识别障碍物、火灾烟雾和地面异常，经 ROI
与规则判定后生成可人工处理的告警、工单和通知。（PRD:11，原文引用；单商场部署口径见导读:7）

- 面客压缩候选（**推断，待批**）：「复用商场现有摄像头，让障碍物、地面异常第一时间被发现、被处置、
  有证据」——压缩自 PRD:30 价值假设，营销化强度待批。

## 2. 目标客户与场景

### 2.1 使用角色（PRD 证据）

| 角色 | 主要任务 | 出处 |
|---|---|---|
| 物业运营/安保人员 | 查看告警、确认误报、处理工单、查看证据图 | PRD:17 |
| 系统管理员 | 管理用户、摄像头、模型、规则和通知配置 | PRD:18 |
| 管理查看者 | 查看看板、告警趋势和设备状态 | PRD:19 |
| 现场实施/运维人员 | 部署、接入摄像头、检查 worker/模型/存储 | PRD:20 |

（当前未建模商场/租户/组织层级，角色仅在单实例范围生效，PRD:22。）

### 2.2 典型场景（PRD 证据）

1. **已实现运营闭环**：摄像头截图 → 定时检测 → DetectionEvent 落库 → ROI/规则判定与 cooldown →
   告警（pending）→ 人工确认或标记误报 → 工单（分配/处理/关闭）→ 企微/邮件/短信通知 + WebSocket
   实时推送（PRD:38-48）。
2. **P0 当前运营闭环六步**（管理员接入摄像头 → 场景配置基线/ROI/规则/通知组 → 计划截图检测 → 事件
   证据留存与告警推送 → 确认/误报/工单闭环 → 看板查看趋势与状态，PRD:69-74）。
3. **第一期试点场景分级**：障碍物停留=旗舰闭环场景；地面脏污=影子模式参与；脏污 YOLO-World 零样本
   评测=纯评测不进闭环；火灾烟雾=纯影子数据积累不进闭环（PRD:120-127）。

## 3. 核心能力卖点（8 条，逐条挂出处）

1. **复用已有摄像头，零新增硬件**：系统价值假设即「复用已有摄像头」（PRD:30）；第一期试点明确不为
   场景新增硬件（PRD:127）。
2. **检测→告警→工单→通知全闭环**：告警四态生命周期（pending/confirmed/false_positive/resolved，
   功能清单:22）；告警确认后建单、分配、状态流转（功能清单:25）；链路全图见 PRD:38-48。
3. **四类检测器**：障碍物检测、YOLO-World 开放词表检测、火灾/烟雾检测（模型质量未量化，功能清单:16）、
   地面脏污图像对比（功能清单:14-18；PRD:55）。
4. **ROI 区域 + 规则引擎可配置**：归一化 [0,1] 坐标 ROI 只对目标区域生效（PRD:78）；停留时长/面积
   超限/禁入区/脏污/火灾规则模板（功能清单:20）；cooldown 抑制短时重复告警 + 人工静默分离
   （功能清单:21；PRD:79）。
5. **证据留痕与人工确认**：证据图、检测事件、CSV 导出（功能清单:23）；高严重级别事件保留人工确认、
   系统不执行消防/门禁等物理控制（PRD:82）——「AI 发现、人决策」叙事锚点（表述**推断，待批**）。
6. **多通道通知 + 实时协同**：企微/邮件/短信实现（短信国内通道待确认，功能清单:26）按严重级别和
   通知组路由（功能清单:27）；WebSocket 实时推送（功能清单:28）。
7. **模型可治理**：模型上传、指派、加载校验、热加载（功能清单:18）；模型变更须记录文件/检测器类型/
   加载校验与生效时间（PRD:81）。
8. **现场推理、数据不出场**：采集、推理、规则、告警和本地证据留在商场内，中心只收元数据/模型版本/
   健康状态（PRD:107）——对隐私敏感客户的差异化锚点（卖点化使用**推断，待批**）。

## 4. 差异化（LnkVision PRD 声明的差异点）

1. **现场推理、中心治理**（冻结架构原则）：不做 SaaS 多租户、不做推理上云（PRD:107）——与云上
   视觉分析方案的根本区别（对比性表述**推断，待批**，原则本身有出处）。
2. **证据链闭环**：把问题证据、确认、处置和通知留在同一条记录链（PRD:30）——区别于「只报警不闭环」
   的告警工具（对比性表述**推断，待批**）。
3. **人工确认机制**：高严重级别保留人工确认，不做自动物理处置、不做消防联动/门禁控制（PRD:82、26；
   功能清单:36）——责任边界清晰。
4. **隐私红线永久冻结**：客流/营销分析、人脸识别、身份追踪、跨摄像头重识别、情绪识别、人口属性推断
   永久 out-of-scope（PRD:145-147）——对甲方隐私审查的差异化姿态。
5. **IP 与合规风险受控**：AGPL 验证期风险受控模式（自营不分发+仓库私有+SBOM 草稿，PRD:113）；目标态
   对齐 NIST AI RMF / Microsoft RAI / EDPB 视频设备指南 / 人脸识别新规（PRD:90-99，**目标态要求，
   非当前实现**，对外表述须带此限定）。
6. **诚实边界（当前不能宣称）**：多租户、多商场控制面、RTSP 视频流、模型质量达标、隐私脱敏、通用
   操作审计、灰度发布、部署交付载体、产品族 capability 接入、商业化就绪均未被当前代码充分证明
   （导读:15-17）——面客叙事的负面清单。

## 5. 客户价值与适用叙事场合

### 5.1 客户价值（PRD 价值假设推导，强度受限）

- **问题定义**（PRD:30）：人工巡检覆盖不足、问题发现晚、证据难留存、闭环责任不清。
- **价值主张**：复用已有摄像头，以可配置检测和规则降低巡检漏检，把证据、确认、处置、通知留在同一
  记录链（PRD:30）。
- **强度限制（硬约束）**：是否「必须使用 AI」待真实场地基线验证（漏检率/误报率/响应时延/运维成本
  对照，PRD:32）；所有目标指标须现场数据和测试协议确定后才能冻结，**不得把「误报率<5%」类目标值当
  当前事实**（PRD:151）——面客材料不得出现任何未冻结量化承诺（此条为红线，非待批项）。

### 5.2 叙事场合建议（**推断，待批**）

| 场合 | 讲法 |
|---|---|
| 公司介绍（AI 产品族矩阵） | 「AI 视觉巡检」格：物业现场的发现与处置闭环，与问数（LnkChatBI）、工作流（MI）、报表（LnkReport）并列构成产品族覆盖面 |
| 方案 PPT（物业/安防场景） | 以 PRD:38-48 闭环链路图为主视觉；场景承诺按 §2.2-3 分级表述（障碍物旗舰 / 脏污影子 / 火灾烟雾影子），严禁并列承诺四类检测同等可用 |
